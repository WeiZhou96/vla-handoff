# vla-handoff

Code and result data for the paper **"Handoff Failures, Repair and Success Criteria for Frozen Vision–Language–Action Policies"** (submitted to *Robotics and Autonomous Systems*).

The study runs a frozen π0.5 policy on CALVIN (and LIBERO-Goal) and

1. restores the exact simulator state at subtask handoffs and re-executes the next subtask with 8 controlled seeds, to split handoff-outcome variance into a handoff-state part and rollout noise;
2. labels repairs drawn from the policy's own instructions with paired counterfactual executions, trains a benefit model and deploys it behind a cost-aware gate;
3. audits CALVIN's start-relative success predicates (criterion A), which credit undo–redo repairs, and defines a handoff-referenced criterion B_def;
4. replays all 8,310 closed-loop chain runs of rounds 1 and 2 bit-exactly (mode A) and re-executes them under B_def (mode B);
5. relabels 2,848 repair branches under B_def, retrains the model and runs a pre-registered third closed-loop round (627 chains × 7 arms).

The repository contains the experiment code as it was run on the GPU server (with path configuration added and comments translated, see [Changes relative to the code as run](#changes-relative-to-the-code-as-run)), the analysis scripts that turn the exported results into every table and quantitative figure of the paper, the result data those scripts read, and the round-3 pre-registration with its lock records.

## Repository layout

```
analysis/        local analysis: statistics, LaTeX table rows, figures (no simulator needed)
data/raw/        result summaries and records exported from the experiment server (only files read by analysis/)
data/derived/    per-chain / per-handoff CSV extracts and the derived JSON written by analysis/compute_*.py
tables/          table rows of the paper (regenerated by analysis/make_tables.py)
figures/         output directory of analysis/fig_*.py (not tracked)
experiments/     server-side experiment code, one folder per experiment stage (folder names as on the server)
prereg/          round-3 pre-registration and lock records
```

## Reproduce the tables and figures (no simulator)

Requires Python 3 (verified with 3.13 on Windows) and the packages in `requirements.txt`.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv\Scripts\pip install -r requirements.txt
cd analysis
python compute_stats.py        # data/derived/*.csv + data/raw/**  -> data/derived/stats.json
python compute_fullchain.py    # full-chain replay records          -> data/derived/fullchain_stats.json, fullchain_per_chain.csv
python compute_round3.py       # round-3, relabelling, offline B    -> data/derived/round3_stats.json
python make_tables.py          # -> tables/*.tex
python fig_decomposition.py; python fig_mechanism.py; python fig_pertask.py
python fig_forest.py; python fig_paired.py; python fig_overview.py   # -> figures/
```

`compute_stats.py` compares its recomputed summaries with the analysis reports produced on the server and stops on any mismatch above 1e-9; `compute_fullchain.py` and `compute_round3.py` run their own consistency checks and stop if one fails. With the pinned package versions, `make_tables.py` reproduces the files in `tables/` byte for byte (up to the platform's line endings); the regenerated JSON files in `data/derived/` differ from the committed ones at most in recorded input hashes and the creation time stamp. The figures use Calibri when it is installed and otherwise fall back to Arial / DejaVu Sans, so glyph shapes can differ from the published figures.

| Paper item | Script | Main input |
|---|---|---|
| Table: predicate audit (`tab_audit_rows`) | compute_fullchain.py → make_tables.py | `data/raw/fullchain_replay_20261010/analysis/records.jsonl` |
| Tables: round 1, round 2 arms, round-2 hypotheses, criterion comparison, replay verification | compute_fullchain.py, compute_stats.py → make_tables.py | full-chain replay summary/records, `data/derived/round*_per_chain.csv` |
| Tables: round-3 hypotheses and arms, relabelling, offline B labels, round-3 timeline | compute_round3.py → make_tables.py | `data/raw/closedloop3_bdef_20261012/analysis/`, `data/raw/relabel_bdef_20261011/analysis/`, `data/raw/benefit_model_bdef_20261011/` |
| Tables: variance decomposition, LIBERO-Goal repair gate | compute_stats.py → make_tables.py | `data/derived/handoffs_j8.csv`, `data/raw/libero_*` |
| Fig. 1 overview | fig_overview.py | `data/raw/case_frames/` (three recorded static-camera frames) |
| Fig. decomposition | fig_decomposition.py | `data/derived/stats.json` |
| Fig. undo–redo mechanism | fig_mechanism.py | `data/raw/fullchain_replay_20261010/analysis/handoff_displacement.json` |
| Fig. first-handoff success (a) and paired chain success (b) | fig_pertask.py, fig_forest.py | `fullchain_stats.json`, `round3_stats.json` |
| Fig. paired outcomes and step costs | fig_paired.py | `fullchain_per_chain.csv` |

`make_tables.py` also writes three tables that are not used in the manuscript (`tab_across_rows`, `tab_scenes_rows`, `tab_vocabnew_rows`).

## Experiment code (`experiments/`)

The simulator experiments ran on a Linux GPU server (Python 3.11, numpy 1.26.4, scikit-learn 1.9.0 as recorded in the round-3 lock; PyTorch, transformers, PyBullet through CALVIN). They cannot be run without the dependencies and checkpoints below, and they were not re-run for this release.

| Folder | Paper section | Content |
|---|---|---|
| `rho/` | Sec. 3.1–3.2 | `envs/s02_calvin.py`: CALVIN scene-D adapter for the frozen π0.5 policy (RLinf/openpi); `s04_replay.py`: exact restoration by replaying the action prefix, physics-vector and image-hash checks, seeding |
| `fix_20260928/` | Sec. 4.3 | `features_patch.py`: DINOv2 patch features; `evaluate_cv.py`: cross-validation protocol over initial configurations |
| `multitask_vocab_20261002/` | Sec. 3.3, 4.1–4.2 | `worker.py`: generic worker (J8 measurement, repair screening, paired label jobs); variance decomposition, verifier scoring and label-branch selection, vocabulary-repair analysis |
| `gating_vocab_20261003/` | Sec. 5.2 | plan of the natural-distribution handoffs used for gate development |
| `benefit_model_20261003/` | Sec. 4.3 | feature extractors (`benefit_lib*.py`) and the A-label benefit models of rounds 1 and 2 |
| `closedloop_20261004/` | Sec. 5.3, 5.5 | round 1: chain plan, configuration lock, workers (`worker_cl.py`, `worker_cl2.py`), analyses |
| `newtasks_20261004/` | Sec. 5.2 | six added target tasks: J8 plan, decomposition, screening and labelling plans; `supervise_multi.py`: GPU job scheduler used by later stages |
| `closedloop2_20261005/` | Sec. 5.5 | round 2: chain plan, configuration lock, pre-registered analysis (runs with `worker_cl2.py`) |
| `crossscene_20261005/` | Sec. 7 | transfer of the round-1 configuration to CALVIN scenes A, B, C under criterion A (not reported in the paper) |
| `netdisp_replay_20261009/` | – | replay of rounds 1–2 up to the first target handoff with net-displacement probes (preparation of the full-chain replay) |
| `fullchain_replay_20261010/` | Sec. 3.4, 5.4, App. B–C | full-chain replay in mode A (criterion A, bit-exact check) and mode B (B_def drives attempts, retries and stopping); `fc_worker.py` contains the B_def / B_orc definitions per target task |
| `relabel_bdef_20261011/` | Sec. 4.2, App. E | re-execution of 2,848 repair branches from stored post-repair states and relabelling under B_def |
| `benefit_model_bdef_20261011/` | Sec. 4.3–4.4, 5.6 | round-3 model on B labels (`train_benefit_v4.py`), δ_B tuning and lock (`lock_config3.py`), chain plan (`plan_cl3.py`), locked configuration and job list |
| `closedloop3_bdef_20261012/` | Sec. 5.6, 6.3, App. F | round-3 worker and the registered analysis |
| `paper_export/` | – | read-only extraction of `data/derived/*.csv` and the case frames from the server results |

Each stage folder was a working directory on the server: the scripts write `results/`, `logs/`, `analysis/` etc. next to themselves and read other stages through the run root. Stages with a `run.sh` are driven by it (`bash run.sh plan|smoke|full|status|analyze ...`); the scheduler and `run.sh` scripts assume GPUs 2–5 (`--order 2,3,4,5`), as on our server.

### Environment variables

| Variable | Used for | Default |
|---|---|---|
| `HANDOFF_RUN_ROOT` | folder that contains the stage folders (code and their outputs) | the `experiments/` folder of this repository |
| `RHO_ROOT` | the `rho` package folder; its parent is put on `sys.path`; also holds `configs/paths.yaml`, `configs/calvin.yaml` and the earlier `outputs/experiments/...` (sequence catalog, development handoffs, cross-validation predictions) | `experiments/rho` |
| `CALVIN_ROOT` | CALVIN checkout (language annotations `calvin_models/conf/annotations/new_playtable_validation.yaml`) | `calvin` (relative to the working directory) |
| `DINOV2_DIR` | DINOv2-small weights | `facebook/dinov2-small` (Hugging Face hub) |
| `HANDOFF_PYTHON` | interpreter used by `run.sh` and the scheduler to start workers | `python` |

The policy checkpoint, RLinf and CALVIN locations are read from `$RHO_ROOT/configs/paths.yaml` (`policy_dir`, `rlinf_root`, `calvin_root`); copy `paths.example.yaml` and `calvin.example.yaml` in `experiments/rho/configs/` and fill them in.

## Data (`data/`)

`data/raw/` holds only the server outputs that the analysis reads: the analysis reports of rounds 1–3, the cross-scene, vocabulary-repair and decomposition reports, the full-chain replay summary and per-run records (`records.jsonl`, one line per round × chain × arm), the relabelling summary, the round-3 offline/tuning/plan reports, the LIBERO-Goal J8 records and gate summary, and three 200×200 static-camera frames. `data/derived/` holds per-chain and per-handoff CSV extracts (`experiments/paper_export/server_extract.py`) and the JSON written by `analysis/compute_*.py`.

Absolute server paths inside these files were replaced by placeholders such as `<HANDOFF_RUN_ROOT>`; nothing else was changed. Some keys and values were written by the experiment code with Chinese labels and are kept verbatim because the analysis scripts look them up:

| Label | Meaning |
|---|---|
| `全部链` | all chains |
| `含 push/rotate 目标的链` | chains with a push or rotation target |
| `不含 push/rotate 目标的链` | chains without a push or rotation target |
| `含 push/rotate 目标（位置 1–4）` | chains with a push or rotation target (positions 1–4) |
| `不含 push/rotate 目标` | without a push or rotation target |
| `push/rotate 合计` | push and rotation targets pooled |
| `其他任务合计` | other targets pooled |
| `全部` | all |
| `层 <task>` | stratum `<task>` |
| `base 此前未出现过` | base configuration not seen before |
| `(不修复)` | (no repair) |
| `A 成立而 B 未成立` / `A 失败而 B 成立` / `B 先于 A 成立` (replay `dv_info`) | first divergence: A satisfied while B_def not / A failed while B_def satisfied / B_def satisfied before A |
| `非机器人接触为空：n / m` (audit flags) | no non-robot contact: at handoff / at start of last attempt |
| `不在源表面：n / m` | block not on its source surface: at handoff / at start of last attempt |
| `有积木已在抽屉：n / m` | a block already in the drawer: at handoff / at start of last attempt |
| `已有积木相互接触：n / m` | blocks already in contact: at handoff / at start of last attempt |
| `累计偏航 \|yaw\|≥180°：n` | accumulated yaw beyond ±180° |

## Pre-registration of round 3 (`prereg/`)

`prereg_round3.md` is the registration as locked (its sha256 equals the value in `prereg_round3.sha256` and in `lock_record.json`). `lock_record.json` (written by `lock_config3.py`) and `lock_addendum.json` (written by `closedloop3_bdef_20261012/run.sh` before the first round-3 job) record the sha256 of the models, configuration, chain plan, label files, reports and code at the time of the lock; see `prereg/README.md` for how these hashes relate to the released files.

## Changes relative to the code as run

- Hard-coded server paths were replaced by the environment variables above (a short configuration block near the top of each affected script and in each `run.sh`); in `run.sh` the inline Python snippets read `HANDOFF_RUN_ROOT` from the environment.
- Chinese comments, docstrings and messages were translated into English; Chinese strings that are written into result files or used as keys were kept (see the glossary).
- The local plotting style was vendored as `analysis/plotstyle.py`.

No computation was changed. Because of these edits, the released files no longer have the sha256 values recorded in the lock records, and the self-checks in `closedloop3_bdef_20261012/` that compare file hashes against `lock_addendum.json` / `locked_config.json` will refuse to run on them; `prereg/README.md` lists the recorded and released hashes.
